# 统一 Agent Loop

`pianchang/agent_loop.py` 是模型驱动的工具控制器。每一步由模型根据用户目标、
最新工程状态、工具目录和历史工具结果决定下一动作。这里使用现有百炼
JSON 输出接口表达动作，未声称使用供应商原生 `tool_calls` 协议。

```text
任务目标 + 工具目录 + 最新状态 + 累积结果
                  ↓
        模型输出一个工具调用或结束请求
                  ↓
      参数校验 → 额度预留 → Trace → 执行工具
                  ↓
      带 call_id 的实际结果加入下一轮上下文
                  ↓
                模型继续
```

## 接入契约

```python
from pianchang.agent_loop import AgentLoop, Tool

tools = [Tool("read_project", "读取工程", {
    "type": "object", "properties": {}, "additionalProperties": False
}, execute=read_project, effect="read")]

loop = AgentLoop(
    text_client, tools, run_directory,
    snapshot=current_project_snapshot,
    finish_check=verify_requested_deliverables,
    progress=publish_progress,    # 可选：接收一个字典
    cancelled=was_cancelled,      # 可选：无参、返回布尔值
)
result = loop.run(goal, max_steps=12, max_video_generations=0)
```

`execute(**arguments)` 只调用已注册的工具。工具效果分为 `read`、`write`、
`video`，模型不能改变分类。工具参数必须符合注册的对象 schema；支持
对象、数组、字符串、整数、数值、布尔、null、枚举及数量/长度上下限。
不执行任意 shell、路径、脚本或模型临时创造的工具。

每轮重新读取 snapshot；状态有变化才把新的完整 snapshot 加入上下文。
每轮保留剩余额度，保留全部先前工具结果。达到上下文大小上限时停止，
不会悄悄删去失败记录后继续。返回给模型的工具结果有明确 `call_id`、
`tool`、`ok`、`result`、`error`，避免把一次操作的结果关联到另一次。

## 完成与停止

- `finish(completed)` 只是模型的请求，必须由独立的 `finish_check()` 返回
  字面布尔值 `complete: true` 批准。检查失败会作为反馈送回模型。
- `inspect` 完成可以表示本次检查已执行，不能表示视频验收通过；`preview`
  完成只是预览导出。检查器需要在结果中明确 `media_accepted` 与创作审阅边界。
- 用户可见完成摘要优先使用独立检查器的 `summary`，避免复述模型夸大的完成声明。
- `needs_input`、`budget_exhausted`、`cancelled`、`error` 都是停止状态，
  `task_complete` 均为 false。达到步数上限不会再发一次额外模型请求。
- 视频额度执行前预留并保存；额度耗尽的调用不执行，拒绝原因回传模型。
  视频工具异常时停止并要求核对已有云端任务，不自动重提交。
- 取消在工具边界检查；已经发出的云端调用不能由此撤销或保证退款。

## Trace 与恢复边界

共享 `trace_system` 记录运行、每轮状态、实际决策、工具输入输出和完成
条件检查。百炼客户端继续记录实际 HTTP 请求、响应和用量。凭证经统一
SDK 脱敏；不记录模型隐藏推理。`TraceError` 向上抛出并阻止后续工具调用。

运行目录额外保存 `run.json`（状态及完整消息）和追加式 `events.jsonl`
（便于工程定位）；它们是业务执行记录，不替代独立 Trace 存储。
`.claimed` 独占标记防止同目录并发执行。已有运行目录禁止自动重放，
进程中断后必须先核对已有工具结果；新任务可通过注册的查询/恢复工具
接续云端任务。当前不实现任意历史进程恢复或自动重试未确认收费操作。

默认 12 个模型决策步骤、0 次视频生成。视频次数是提交动作上限，不是
人民币费用上限；文本决策、视觉观察及已提交视频可能分别计费。

## 在工作台使用

1. 打开 `http://127.0.0.1:8765/`，选择已有故事，进入「05 Agent 执行」。
   新故事先在「01 创意与剧本」生成制作工程。
2. 填写这次目标，选择交付范围。首次可使用「仅检查现有素材」，目标写：
   “逐个检查所有已选镜头，汇总失败和未知项，形成检查报告。”
3. 设置决策轮数和视频生成调用上限。检查模式固定为 0 次视频生成；
   需要画面语义观察时勾选视觉模型选项。
4. 点击「启动 Agent」。在制作动态查看当前动作，点击「查看本次 Trace」
   查看每轮完整模型请求、响应、工具参数、工具结果及完成条件检查。
5. 「停止后续动作」在当前调用结束后生效。已提交的生成任务会保留，
   后续新任务可以查询已有候选，不能把停止理解为取消云端生成。

`pianchang/drama_tools.py` 提供当前工程限定的工具：读取工程、查询剧情状态、修改
本次生成提示、生成视频、续查云端任务、提取媒体证据、检查镜头、选用候选、
导出预览。生成和续查只产生候选，不改变显式选用关系；模型需要另行调用
`select_candidate`。状态中标明工作台默认候选回退与显式选用的区别。

接口为 `POST /api/projects/{project_id}/agent`，请求字段如下：

```json
{
  "goal": "逐个检查所有已选镜头，汇总失败和未知项",
  "mode": "inspect",
  "max_steps": 12,
  "max_video_generations": 0,
  "with_model": false
}
```

`mode` 支持 `inspect`、`preview`、`accepted`。Web 限制决策轮数为 1～30，
视频生成调用为 0～10。目标文字用于模型规划；独立完成检查器核对所选交付
范围与已有镜头验收契约，不会自动把任意自然语言要求转换成可靠的测试。
`accepted` 要求当前选用镜头的必过检查通过并导出对应预览，但不代表整片
叙事、节奏、表演和人工创作审看已通过。

当前尚无图像编辑、配音、口型同步或自由修改剧本的工具。云端视频续查每次
只查询一次，长任务可能在本次轮数耗尽前仍未完成；系统保留任务 ID 和证据，
如实返回未完成，由后续任务继续查询。

## 剧本入口的修复循环

「01 创意与剧本」由 `StoryRunner` 执行有次数限制的生成—校验—修复循环；
它没有使用本文件所述的通用工具决策协议。草稿的结构或数量校验失败时，
原始模型输出与结构化错误（包含 path、expected、actual）会进入下一轮
模型上下文。历史输出和错误持续保留，直到检查通过或修复额度耗尽。
随后制作规格阶段另有独立的修复额度，冻结剧本与验收规则不可修改。

Web 每阶段最多修复 2 次。失败草稿的“自动修复这份草稿”提交
`POST /api/projects`、`{"repair_from":"原任务ID"}`；服务端恢复原始参数
并锁定草稿哈希，在新目录保存修复版本，保留原任务与 Trace。输入来源不明、
未确认的计费调用、网络异常或 Trace 写入失败会停止，而不会无限重试。
草稿阶段通过只代表结构和数量满足约束，不能证明剧情语义或媒体质量通过。
